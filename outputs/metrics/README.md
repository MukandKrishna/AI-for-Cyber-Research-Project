# Grouped Evaluation Outputs

These files were generated by:

`../../../src/evaluation/grouped_evaluation_pipeline.py`

Input feature table:

`../../features/pair_level_features_enhanced.csv`

## Fold Design

The evaluation uses 5 grouped folds based on the `folder` column.

Each fold:

- holds out one complete `Dataset-*` folder for testing
- trains on the other four folders
- avoids mixing rows from the same dataset folder across train and test
- contains 88 training rows and 22 test rows
- contains 8 training positives and 2 test positives

This matches the project methodology and avoids dataset-folder leakage.

## Files

- `feature_columns.csv`  
  Numeric modelling features, excluding IDs, labels, timestamps, and text labels.

- `feature_columns_no_length.csv`  
  Numeric modelling features used for the no-message-length ablation.

- `feature_columns_removed_for_no_length_ablation.csv`  
  The 13 message-length-related features removed for the ablation experiment.

- `fold_assignments.csv`  
  The official 5-fold train/test folder split.

- `baseline_predictions_by_fold.csv`  
  Per-pair baseline scores and within-scenario ranks for each held-out fold.

- `baseline_fold_metrics.csv`  
  Fold-level ranking and top-1 metrics for each baseline.

- `baseline_metrics_summary.csv`  
  Mean and standard deviation of each baseline metric across the 5 folds.

- `model_predictions_by_fold.csv`  
  Per-pair model scores and within-scenario ranks for Random Forest, SVM, and MLP.

- `model_fold_metrics.csv`  
  Fold-level ranking, top-1, ROC-AUC, and PR-AUC metrics for each trained model.

- `model_metrics_summary.csv`  
  Mean and standard deviation of each trained-model metric across the 5 folds.

- `all_fold_metrics.csv`  
  Combined baseline and trained-model fold metrics.

- `all_metrics_summary.csv`  
  Combined baseline and trained-model summary metrics.

- `full_vs_no_length_comparison.csv`  
  Direct comparison of full-feature and no-length model performance.

## Baseline Interpretation Note

The short-message, mean-message-length, and weighted contextual baselines perform perfectly on the current enhanced feature table.

This should be reported carefully. It is useful evidence, but it may also indicate that the synthetic PASYDA data contains a strong message-length artefact. The final report should discuss this as a dataset limitation rather than claiming the real-world grooming problem is solved by message length alone.

## Model Interpretation Note

Random Forest, SVM, and the small MLP perform perfectly on the full enhanced feature table.

This is strong evidence that the engineered features identify the labelled PASYDA pairs under grouped evaluation. However, because simple message-length baselines also perform perfectly, the no-length ablation should be used to qualify the conclusion. Random Forest and MLP performance drops without length-related features, while SVM remains perfect.
